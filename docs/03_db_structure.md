쓰되 **원래의 층 구조가 달라** ID 체계가 갈린다.

## 5-2. 페이지 식별 체계

### 파일명 — A · C · Z

페이지 이미지의 파일명은 **본문 쪽 번호와 일치하도록** 지었다. 연구자가 텍스트의 어느 자리를
원본에서 확인하려 할 때, `page_info`의 숫자를 그대로 파일명으로 읽으면 되게 하기 위해서다.

| 접두 | 뜻 | 1915 | 1924 |
|---|---|---:|---:|
| **A** | 본문 앞 (표지·목차·머리말 등) | 11장 | 6장 |
| **C** | **본문** — 번호가 인쇄된 쪽 번호와 같다 | 796장 | 281장 |
| **Z** | 본문 뒤 (판권지·광고 등) | 25장 | 3장 |
| | 계 | **832** | **290** |

곧 인쇄본 235쪽을 보려면 `C235`를 열면 된다. 앞뒤의 쪽은 인쇄 번호가 없거나 별도 체계이므로
A·Z로 갈라 본문 번호와 충돌하지 않게 했다.

**대응 확인** — `page_info`의 숫자 범위가 C의 장수와 맞물린다.

| | 파일명 | `page_info` 숫자 범위 |
|---|---|---|
| 1915 | C001 ~ C796 | 2 ~ 796 |
| 1924 | C001 ~ C281 | 1 ~ 282 |

⚠️ **재넘버링 스크립트는 확인되지 않았다.** 분할 결과(`0001_1.jpg`·`0001_2.jpg` 형식)에서
A/C/Z 이름으로 바꾸는 코드가 남아 있지 않다. 규약 자체는 위 대응이 증명한다.

### `page_info` — 접두를 보존하며 증가한다

DB 생성 스크립트(`scripts/04_build_db/a_inoue_final_runner.py`)가 판독 텍스트의 페이지 태그를
읽어 `page_info`를 채운다. 시작값은 `a0`이고, 증가는 이렇게 한다.

```python
def _increment_page(self, page_str):
    if page_str.isdigit():                    # "10" → "11"
        return str(int(page_str) + 1)
    match = re.search(r'(\d+)$', page_str)    # "a4" → 접두 "a" + 4
    prefix = page_str[:match.start()]
    return f"{prefix}{new_num}"               # → "a5"
```

곧 `a0 → a1 → … → b1 → … → 1 → 2 → …`로 이어지며, **접두가 있으면 유지하고 숫자만 올린다.**
파일명의 A/C/Z 규약이 텍스트 쪽에서도 같은 방식으로 살아 있다.

### 걸침 표기 — `100-101`

`page_info`에 `100-101`처럼 두 쪽이 적힌 값이 있다. **한 문장이 쪽을 넘어간 경우**다.

| 페이지 태그의 자리 | `page_info` |
|---|---|
| 문장 **끝**에 있다 | `100` — 그 쪽에서 문장이 끝났다 |
| 문장 **중간**에 있다 | `100-101` — 문장이 두 쪽에 걸쳤다 |

이 규칙은 판독 후처리의 이어 붙이기와 짝을 이룬다. 후처리가 쪽 경계에서 잘린 문장을 이어
놓고([`02_digitization.md`](02_digitization.md) ③), DB 생성이 그 문장의 쪽을 범위로 기록한다.

## 5-3. 도식(圖)의 처리

두 책에는 본문이 가리키는 **도식**이 있다. 1915년 66쪽과 1924년 96쪽의 현상즉실재론 도식이
대표적이며, 선행연구가 두 책의 관계를 처음 밝힐 때 맞댄 것이 바로 이 둘이다.

**이미지 자체는 DB에 들어가지 않는다.** 대신 **자리표시자와 그 안의 글자**를 두 행으로 적었다.

```
C02-P31-S01  p.66  [TEXT]        {{FIG:Inoue_Metaphysics_01 | TYPE:Trialism | LOC:p66}}
ANNO         p.66  [ANNOTATION]  精神
```

형식은 `{{FIG:<이름> | TYPE:<유형> | LOC:p<쪽>}}`이고, 바로 다음 행에 도식 안에 적힌 글자가
온다. 본문의 「上圖와 가티」·「簡單に圖に書けば斯うなる」가 이 행을 가리킨다.

**실물 이미지는 `data/2_cut_renumbering/`에 있다.** `LOC`의 쪽 번호가 곧 파일명이므로,
`LOC:p66`은 `PR_cut_renumber/C066.jpg`다(§5-2).

| | 자리표시자의 `line_class` | 개수 |
|---|---|---|
| 1915 | **`TEXT`** | 11 |

같은 성격의 행인데 분류가 갈린다. 결과가 둘로 나온다.

1. **1915년 자리표시자 11행은 본문 행으로 세어진다.** `TEXT` 10,976 안에 들어 있고

도식 안의 글자(`物質` 등)도 `ANNOTATION`이라 정규화 대상에서 빠진다.

곧 **어긋남은 문장·묶음 수에만 걸리고 어휘 통계에는 걸리지 않는다.** 그래도 같은 성격의 행이
두 책에서 다르게 분류된 것은 사실이며, 여기 적어 둔다.

- `line_class`를 한쪽으로 통일할 것인가 — 통일하면 1915년의 문장 수와 묶음 배정이 바뀐다.
- 자리표시자와 `data/2_cut_renumbering/`의 이미지를 **파일 경로로 잇는 것** — 지금은 `LOC`의
  쪽 번호를 사람이 읽어 찾아가야 한다.

## 6. ID 체계

### 1915

```
C##-P##-S##          기본 — 절이 없는 장
C##-S##-P##-S##      절이 있는 장
```

**절이 있는 장은 넷뿐이다** — C01(序論·第一·第二) · C13(一~六) · C14(一~五) · C20(一~四).

### 1924

```
C##-S##-I##-P##-S##      장-절-항-문단-문장
```

### 통합본에서의 처리

여러 자료를 함께 다루기 위해 1915년 책에 **`I00`을 강제로 넣어** 다섯 단으로 맞췄다.
`C02-P19-S04` → `C02-S00-I00-P19-S04`.

**이 `I00`은 실재하는 층이 아니라 자리맞춤이다.** 1915년 책에서 항 단위 분석을 시도해서는 안
된다.

### 묶음 ID

```
n_chunk_id = C##-S##-I##-N##
```

- 연속 **다섯 문장**을 한 묶음으로 자른다(비중첩).
- 묶음 번호는 **항(I) 단위로 초기화**한다.
- 마지막 자투리는 문장 수가 3 이상이면 독립 묶음, 2 이하면 앞 묶음에 합친다.

결과는 1915년 **2,195묶음**, 1924년 **424묶음**이다.
