# 02b. 잡지의 디지털화 절차

『개벽』과 『천도교회월보』가 텍스트가 되기까지의 과정이다. **두 잡지의 경로가 서로 다르고,
[두 단행본](02_digitization.md)과도 다르다.** 그 다름이 자료의 성격을 가르므로 따로 적는다.

```
『개벽』     기존 디지털 원문을 수집          → 판독 단계 없음
『천도교회월보』  세로쓰기 옛한글 지면을 판독      → 3엔진 합의 + 사람 중재
두 단행본     펼침면 지면을 판독               → 단일 엔진 + 여러 판 교정
```

---

## 1. 『개벽』 — 판독하지 않는다

### 출처

**국사편찬위원회 한국사데이터베이스**(`db.history.go.kr`)의 디지털 원문이다. 스캔 이미지를
판독한 것이 아니라 **이미 텍스트로 제공되는 것을 받아 온 것**이다.

```
scraper/scrape_articles.py   →  raw/articles/<자료ID>.json   2,516편
                                raw/manifest_20260429.tsv    (2026-04-29 수집)
```

manifest는 `자료ID · 잡지명 · 발행일 · 기사제목 · 필자 · 기사형태 · URL` 일곱 열이고, 개별
`.json`은 이렇게 생겼다.

```json
{ "doc_id": "ma_013_0010_0001",
  "url": "https://db.history.go.kr/id/ma_013_0010_0001",
  "fetched_at": "2026-04-29T10:36:14+09:00",
  "meta": { "magazine_name": "개벽", "issue_label": "개벽 제1호", "issue_number": 1, … },
  "body_full": "…",
  "paragraphs": [ { "seq": …, "text": …, "is_heading": …, "page_markers": … } ] }
```

**문단 구획과 쪽 표시가 원본 DB에 이미 들어 있다.** 두 단행본에서 판독으로 얻어야 했던 것이
여기서는 주어진다.

### 74편을 고른 방법

2,516편 가운데 **필자명이 다음에 걸리는 글**을 뽑았다.

```python
YID_AUTHORS = ('李敦化', '夜雷', '야뢰', '白頭山人', '백두산인',
               '滄海居士', '창해거사', '猪巖', '저암')
```

한자와 한글 표기를 함께 둔 것은 DB의 필자 표기가 일정하지 않기 때문이다.

> 🔴 **이 목록이 코퍼스의 경계를 만든다.** 발표문이 「이돈화의 글에 井上이 한 번도 나오지
> 않는다」고 할 때 그 「글 전체」는 이 아홉 낱말에 걸린 74편이다. **`東洋室主人`이 목록에 없어
> 「今後의 天道敎」(제28호)가 코퍼스 밖에 있는 것**도 여기서 비롯한다.

### 변환

`scripts/convert_gaebyeok_to_unified.py`

1. `paragraphs` 단위로 본문을 분해한다
2. 각 문단의 텍스트를 **문장 단위로 다시 나눈다** — 어미 종결 + 구두점
3. `local_id = C##-S00-I00-P##-S##`. **절 식별은 하지 않아 `S00`으로 일관한다**
4. `n_chunk_id` — 한 글 안의 모든 본문 문장을 모아 다섯 문장 비중첩 묶음. 자투리가 셋 미만이면
   앞 묶음에 합친다
5. **글 번호 `C`는 발행일 순**이다

## 2. 『천도교회월보』 — 3엔진 합의로 판독한다

세로쓰기에 옛한글이 섞인 지면이라 판독이 가장 어려운 자료다. 그래서 절차가 가장 두껍다.

### 단계

```
① 지면 확보        국립중앙도서관 등
② 단(段) 분리      cut_units.py · fill_units_default_{dual,single}band.py
                   → units/ 에 5단 이미지
③ 3엔진 판독       Claude Opus(주) · Gemini 2.5 Pro(보강) · PaddleOCR(검증)
                   → ocr/<도구>/ 에 각각의 결과
④ 합의            consensus.py — 도구 간 차이 영역을 검출해 review 보고서 생성
⑤ 사람 중재        ⚠️ 마커를 이미지와 대조해 해소 (9편만 완료 — 아래 「검수 현황」)
⑥ 고충실 전사본     transcripts/*.high_fidelity.md      ← 권위 텍스트
⑦ 현대 독해본       transform_old_to_modern.py + add_spacing.py
                   → transcripts/*.modern_reading.md
```

**GPT-5는 시험했으나 시리즈에서 제외했다.** 결과는 `ocr/gpt5/`에 참고용으로 남아 있다.

### 권위 문서

- 시리즈 정책 v0.3 (20개 규칙) — `_design/2026-05-09_cheondogyo_wolbo_consensus_policy_v0_3.md`
- 옛한글 자모 매핑 규칙표 v1.0 (18개 매핑) — `scripts/transform_old_to_modern.py` 안의 dict

### 판별 표시

각 편의 전사본은 판을 이름에 달고 있다.

| 판 | 뜻 |
|---|---|
| `high_fidelity.draft_v0.md` | Claude OCR 본에서 뽑은 초벌. `⚠️` 마커로 불확실한 자리를 표시 |
| `high_fidelity.md` | **사람 검수 완료.** `⚠️` 마커 없음 |
| `modern_reading.md` | 옛한글을 현대 표기로 옮기고 띄어쓰기를 넣은 판 |

**DB의 `src_metadata`에 들어 있는 `version` 필드가 이 판을 그대로 표시한다** —
`v0_claude_base`는 초벌, `v1_unit_partial`은 부분 단위 판이다.
[`06_ai_disclosure.md`](06_ai_disclosure.md) §4 참조.

### 검수 현황 — 대부분이 초벌이다

⚠️ **86편 가운데 사람이 전문을 원문과 대조해 마친 것은 아홉 편이다.** 나머지는 세 엔진이
갈린 자리가 편당 수백 곳 남아 있고, **코퍼스에는 그 가운데 한 엔진의 판독이 들어가 있다.**
곧 **월보 코퍼스는 초벌 위에 서 있다.**

이것을 감추지 않는 까닭은, 이 자료로 무엇을 할 수 있고 무엇을 할 수 없는지가 여기서
갈리기 때문이다.

| | 초벌로도 되는 것 | 초벌로는 안 되는 것 |
|---|---|---|
| | 어느 편에 어떤 어휘가 있는지 훑기 | 특정 낱말의 **빈도를 수치로** 말하기 |
| | 후보를 좁혀 원문을 볼 자리 고르기 | **원문 대조 없이 인용**하기 |
| | 「어디에 있는가」 | 「**없다**」고 단정하기 |

특히 **「없다」는 판정에 주의해야 한다.** 어떤 낱말이 0회라는 사실은 원문에 없다는 뜻일 수도
있고 판독이 다르게 읽었다는 뜻일 수도 있다.

**남은 눈 판단을 기계가 어디까지 줄일 수 있는지**는 따로 재 보았다 —
[`../data/5_magazine_sources/wolbo/marker_resolution_experiment.md`](../data/5_magazine_sources/wolbo/marker_resolution_experiment.md).
요지는 **이미지로 푸는 문제(한자·음절)와 문법으로 푸는 문제(종성 유무)가 다르다**는 것이고,
검수 범위를 54편에서 85편으로 넓혀야 하는 이유도 그 문서 §7에 적었다.

**그래서 인용은 편 단위 검수와 별도로 대목마다 지면을 대조한다.** 그 기록이
[`../data/5_magazine_sources/wolbo/verified_passages.md`](../data/5_magazine_sources/wolbo/verified_passages.md)에
있다. 대조를 마친 대목만 그 파일에 들어가며, **거기에 없는 대목은 대조하지 않은 것이다.**

### 미완인 채로 내놓는다 (2026-08-12)

검수가 끝나기를 기다리면 이 자료는 아무도 쓰지 못한다. 그래서 **86편 전부를 쓸 수 있는
형태로 내놓되, 어디가 어느 등급인지를 글자마다 표시**했다. 셋을 새로 만들었다.

| | 무엇 | 어떻게 |
|---|---|---|
| [`reading/`](../data/5_magazine_sources/wolbo/reading/) | 읽을 수 있는 본문 86편 | 마커를 해소하고 〔규칙〕〔대장〕〔C〕〔G〕〔?…〕〔확인〕으로 해소 방식을 표시 |
| [`keyword_index.csv`](../data/5_magazine_sources/wolbo/keyword_index.csv) | 키워드 색인 (17낱말·1,219출현) | **합의본이 아니라 엔진 원출력**을 세어 마커의 과소 계수를 피한다 |
| [`CORPUS_STATUS.csv`](../data/5_magazine_sources/wolbo/CORPUS_STATUS.csv) | 편별 대시보드 | 마커·대분기·자동해소율·엔진 공백률·대조 자리 |

읽는 법은 [`TRUST.md`](../data/5_magazine_sources/wolbo/TRUST.md)에 모았다. 실측은 이렇다 —
초벌 76편의 마커 **14,588** 가운데 규칙·대장으로 판단이 필요 없던 것이 21.7%, **기계가
한쪽을 고른 것이 69.0%**, 아무도 고르지 못한 대분기가 7.1%다. 마커 해소 규약은
`scripts/06_magazines/wolbo_markers.py`가 `verified_transcripts/_ruleset.md`를 코드로 옮긴
것이며, **규약이 권위이고 코드가 그것을 따른다.**

이 셋은 **파생물**이다. 낡으면 고치지 말고 다시 생성한다.

### 검수한 아홉 편은 어디에 있나

| | 어디 |
|---|---|
| **정본 8편** (C30~C37, 1915~1917) | [`../data/5_magazine_sources/wolbo/verified_transcripts/`](../data/5_magazine_sources/wolbo/verified_transcripts/) |
| 정본 1편 (C01) | `articles/01_kwonyu_1911-01/transcripts/article_01.high_fidelity.md` |
| 초벌 77편 | `articles/*/transcripts/*.high_fidelity.draft_v0.md` |

정본의 조건은 **잔여 `⚠️`·`@`·`draft_v0`가 없고 프론트매터가 `status: human_verified`인 것**이다.
그 조건과 검수 파이프라인 4단(구조 선분리 → 자동채움 → 눈 판단 → 정본화)을 정한 문서가
`verified_transcripts/_ruleset.md`이며, **자동화는 그 규약의 확정 규칙에만 적용하고 규칙 밖은
전부 사람 눈으로 넘긴다**는 것이 요점이다. 정본과 초벌·지면의 대응은 같은 폴더의 `MAP.csv`에
있다.

🔴 **다만 이 정본 여덟 편은 아직 코퍼스에 들어가 있지 않다.** 아래 「변환」이 `high_fidelity.md`를
우선하는데 그 파일이 `articles/` 밖에 있어, **`MA_YD_10-20_WB.xlsx`는 이 여덟 편에 대해서도
초벌 위에 서 있다.** 정본이 실제로 DB에 반영된 것은 C01 한 편뿐이다. 곧 **「9편 검수 완료」는
검수의 사실이지 코퍼스의 상태가 아니다.** 정합을 맞추려면 정본을 `articles/`로 옮기고 변환을
다시 돌려야 하며, 그러면 DB 위에서 낸 수치가 달라진다.

**여덟 편에는 唯物·唯心·實在·物心·三派가 0회다.** 그 구간(1915~1917)에 관해서만은 「없다」는
판정이 초벌이 아니라 정본 위에 선다. 다만 검수 대상이 그 어휘를 기준으로 골라진 것이 아니므로
(시리즈 순서와 우선순위 `core` 5편) 우연한 겹침이다.

### 변환

`scripts/convert_wolbo_to_unified.py`

1. `series_index.csv`를 발행일 순으로 정렬해 `C` 번호를 매긴다
2. `articles/` 폴더를 훑는다 — **정본 `*.high_fidelity.md`를 우선하고 없으면 초벌
   `*.high_fidelity.draft_v0.md`를 쓴다.** 초벌에서는 `⚠️[C:…|G:…]` 마커 안의 **Claude 판독**을
   집는다. ⚠️ 현재 정본이 `articles/` 안에 있는 것은 C01 한 편뿐이다(위 참조)
3. 본문을 추출한다(프론트매터와 `[body]` 분리, `draft_v0`는 `⚠️` 마커 처리)
4. 문장 분리 + 다섯 문장 묶음
5. `local_id = C##-S00-I00-P00-S##`. **단락 정보가 없어 `P00`으로 일관한다**

## 3. 세 자료의 차이가 남기는 것

| | 두 단행본 | 『개벽』 | 『천도교회월보』 |
|---|---|---|---|
| 지면 판독 | Gemini 3.0 | **없음** (디지털 원문) | Claude·Gemini·Paddle **3엔진 합의** |
| 사람 검수 | 여러 판에 걸쳐 | — | **86편 중 9편**(나머지는 초벌) |
| 장·절·항 | 있음 (판독이 인식) | **없음** (`S00` 일관) | **없음** (`S00`·`P00` 일관) |
| 문단 구획 | 판독이 준다 | **원본 DB가 준다** | **없음** (`P00`) |
| 쪽 정보 | 인라인 태그 | 원본 DB의 `page_markers` | — |
| 판별 표시 | 파일명 | — | **행 메타의 `version` 필드** |

### 이 차이가 분석에 미치는 영향

**① 계층 분석은 두 단행본에서만 가능하다.** 잡지는 `local_id`의 절·항 자리가 비어 있으므로
장(글) 단위 아래로는 나눌 수 없다.

**② 문단 단위 비교는 개벽에서만 가능하다.** 월보는 `P00`으로 일관해 문단이 없다. 다섯 문장
묶음이 유일한 하위 단위다.

**③ 월보의 묶음은 다른 자료와 등가가 아니다.** 세로쓰기 고문체라 문장 종결 부호가 없어
「다섯 문장」이 거대 블록이 된다(고유 토큰 중앙값 90, 개벽 28의 약 세 배). 그래서 묶음 단위
비교에는 **28토큰 윈도우로 재분할**한 판(`tokens_월보_win.csv`)을 쓴다.

**④ 판독 위험이 자료마다 다르다.** 『개벽』은 판독 단계가 없어
[`06_ai_disclosure.md`](06_ai_disclosure.md)의 ③④⑤가 적용되지 않는다. 두 단행본은 단일 엔진에
여러 판 교정을 얹었다. 월보는 3엔진이 서로를 견제했으나 **그 차이의 대부분이 아직 사람 손을
거치지 않았다**(86편 중 9편). 위험의 형태가 셋 다 다르며, **월보 쪽이 가장 무르다.**

| **지면 무결성 대장** (`wolbo54_status/` — SHA-256 · v2 차단 기록) | **288면** |
| **마커 자동 해소 실험** (`marker_resolution_experiment.md` · `marker_decisions.csv`) | **656건** |
| `series_index.csv` · 배치 요약 · 키워드 감사 | |

**원본 지면이 있다는 것이 이 자료의 요점이다.** 국립중앙도서관 스캔이며 `meta.json`에 서지가
함께 있다. 판독이 갈린 자리에서 **어느 쪽이 맞는지 남이 판정할 수 있다.**

**차이 검토 보고서가 이 자료의 값이다.** 세 엔진이 같은 자리를 어떻게 다르게 읽었는지가 글자
단위로 적혀 있다.

```
| # | tag     | Claude   | Gemini  | Paddle 지원 |
| 1 | delete  | 講演      | ∅       | C:講, C:演   |
| 3 | replace | 呵呵      | 呱呱     | G:呱, G:呱   |
| 4 | replace | ᄒᆞ니     | 홈이     | -           |
```

**곧 월보는 판독의 불확실성이 어디에 있었는지를 자리마다 보여 준다.** 두 단행본은 판이 여덟
개 있을 뿐 무엇이 왜 바뀌었는지는 판을 대조해야 알 수 있다. **이 점에서 월보 쪽이 두
단행본보다 촘촘하다.**

### 단 이미지를 싣지 않는 까닭

판독의 직접 입력은 지면이 아니라 **단(段) 이미지**다(`units/*.png` 643장, 1.3GB). 그것을 싣지
않고 **원본 지면을 실은 것은 판단이며, 근거는 셋이다.**

| | 단 이미지 | 원본 지면 |
|---|---|---|
| 성격 | 우리가 자른 **파생물** | **국립중앙도서관 원본** |
| 용량 | 1.3GB | **109MB** |
| 권위 | 없음 | 있다 |
| 재현 | — | `meta.yaml`의 자르기 좌표와 `bands_per_page`로 **단 이미지를 다시 만들 수 있다** |

**① 검증의 목적에는 원본이 낫다.** 「`呵呵`인가 `呱呱`인가」는 지면을 봐야 판정된다. 파생물로는
원본과 대조할 길이 없다.

**② 재현된다.** `meta.yaml`이 쪽별 SHA-256과 픽셀 크기까지 적으므로, 지면의 무결성을 확인한 뒤
좌표대로 자르면 같은 단 이미지가 나온다.

**③ 용량이 열두 배 차이다.** 1.3GB를 얹으면 저장소가 2GB를 넘어 clone 자체가 부담이 된다.

⚠️ **단 이미지가 고유하게 답하는 것이 하나 있다** — 「엔진이 실제로 무엇을 봤는가」다. 자르기가
어긋나 글자가 잘렸다면 지면을 봐서는 모른다. 실제로 부 표본에서 자르기를 정정한 일이 있다
(`samples/oldhangul_sample_wolbo18/`의 「정정된 자르기」). 다만 그것은 드문 진단이고, 그 값을
위해 1.3GB를 얹는 것은 균형이 맞지 않는다고 보았다.

### 그 밖에 없는 것

- **개벽 나머지 2,442편의 원본** — manifest에 목록이 있고 국사편찬위에서 누구나 받을 수 있다.
