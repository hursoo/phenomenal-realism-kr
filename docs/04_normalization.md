# 04. 토큰화와 정규화

DB의 문장을 **비교 가능한 낱말의 집합**으로 바꾸는 단계다. 유사도 수치는 전적으로 이 단계의
설계에 달려 있으므로, 무엇을 한 낱말로 세었고 무엇을 버렸는지를 여기서 밝힌다.

> 권위 문서: `normalization_spec_2026-05-21.md` (§0~§9). 이 문서와 상충하면 그쪽이 우선한다.
> 구현: `scripts/step2_build_norm_tokens.py`.

**원칙 — raw 불변.** 정규화는 원본이나 DB를 고치지 않는다. 파생 토큰 층
(`data/4_tokens/tokens_*.csv`)으로만 산출한다.

---

## 1. 두 방식이 있다

이 저장소의 수치는 **두 가지 토큰화** 위에서 나온다. 어느 쪽 산출물인지 반드시 확인해야 한다.

| | 표기 방식 (한자-only) | 정규화 방식 (reading-space) |
|---|---|---|
| 규칙 | `[一-鿿]{2,}` — 두 자 이상 한자 연쇄 | 모든 한자를 **한국 한자음 한글**로 변환 |
| 예 | `唯物論` | `유물론` |
| 성격 | 초기 방식 | 2026-05 이후의 정본 |
| 쓰임 | robustness 비교본 | 공유 토큰 층 |

**둘 다 남긴다.** 두 방식에서 결론이 같다는 것 자체가 검증이기 때문이다(§6).

---

## 2. 왜 정규화가 필요했나

### 문제 — 표기 밀도의 비대칭

같은 낱말을 자료마다 다르게 적는다. 한자 표기 비율이 이렇게 갈린다.

| 개벽 | 1915 | 월보 | 1924 |
|---|---|---|---|
| 39% | **100%** | 59% | 45% |

한자로 적힌 것만 뽑으면 **한자를 많이 쓴 자료가 더 닮았다고 판정될 편향**이 생긴다. 「유물론」을
한글로 적은 대목은 세어지지 않고 「唯物論」으로 적은 대목만 세어지기 때문이다.

이 편향은 유사도(§2 자카드)보다 **빈도 분석에 더 치명적**이다. 횟수가 통째로 왜곡된다.

### 진단

- 코퍼스 한자 토큰 **39,097종** / 단자 3,900종
- 한자 → 한국음 변환 성공률 **100%**
- 한글 복구 게이트를 통과한 것 **약 1,131 출현**

곧 **누락된 한자어 편향은 실재하나 제한적**이다. 표기 밀도 격차의 큰 몫은 애초에 배제해야 할
**고유어 문법층**이었다.

---

## 3. 캐노니컬 공간 — 왜 한글 쪽으로 내렸나

두 방향이 가능했다.

- **한자-UP** — 한글로 적힌 것을 한자로 끌어올린다.
- **reading-DOWN** — 한자로 적힌 것을 한국 한자음 한글로 내린다.

**한자-UP은 실패했다.** 자동 이체자 검출을 시도했으나 한국 한자음의 동음이 너무 과밀해
**佛↔不, 信↔神, 義↔意를 잘못 병합**했다.

**reading-DOWN을 채택했다.** 같은 동음성이 이번에는 **통합기**로 작동한다.

1. **일본어 한자도 같이 내려온다.** `唯物論`(일) · `唯物論`(한) · `유물론`(한)이 모두 「유물론」으로
   수렴한다. **별도의 대응표가 필요 없다 — 변환 함수 자체가 두 언어의 다리다.**
2. **이체자가 자동으로 통일된다.** 道德=道徳 · 説明=說明 · 慾望=欲望 · 裡面=裏面 · 根底=根柢 ·
   絶對=絕對 · 特徵=特徴 · 軆面=體面 · 槪念=概念 · 自體=自軆 · 大槪=大概 · 內部=内部.
3. **읽기를 보존한 판독 오류가 흡수된다.** `衣識` → 「의식」 → `意識`과 합류한다.

가나는 버린다. 일본어의 문법층은 한국어의 조사·어미에 해당한다.

> 이 설계가 이 연구를 가능하게 한다. 일본어 책과 국한문 책을 곧바로 맞댈 수 있는 근거가
> **한자어라는 공통 의미 단위**이고, 그 단위를 실제로 만드는 것이 이 변환이다.

## 4. 세 가지 장치

### 4.1 동음 게이트 — 고유어를 걸러낸다

한글 어절을 무조건 한자어로 복구하면 **고유어와 문법형이 한자 읽기와 우연히 겹쳐** 대량 오인정이
난다. 그래서 조건을 걸었다.

> 그 읽기를 내는 한자 단어가 코퍼스에 있고, **또한 한자 형태의 최대 빈도 ≥ 한글 형태의 빈도**일
> 때만 복구한다.

| 판정 | 예 |
|---|---|
| 제외 | 「하고」 1,250회 vs `何故` 191회 → 한글이 압도 → 고유어로 보아 버린다 |
| 복구 | 「만일」 103회 vs `萬一` 134회 → 한자가 우세 → 한자어로 복구한다 |

복구된 예: 만일 · 대개 · 역시 · 지금 · 본래 · 원래 · 자기 · 당시 · 의의 · 정신적 · 창조적 ·
사회적 · 민족적 · 세계 · 가치 · 시대 · 지도 · 소위 · 물론 · 과연 · 내지.

### 4.2 동음이의 예외 20 — 합치면 안 되는 것

읽기가 같아도 뜻이 다른 스무 쌍은 **한자 형태를 그대로 유지**한다.

| 읽기 | 유지 | | 읽기 | 유지 |
|---|---|---|---|---|
| 이상 | 理想 / 以上 | | 일절 | 一切 / 一節 |
| 주의 | 主義 / 注意 | | 동양 | 東洋 / 同樣 |
| 조선 | 朝鮮 / 祖先 | | 구주 | 歐洲 / 九州 |
| 자신 | 自身 / 自信 | | 신도 | 神道 / 信徒 |
| 식물 | 植物 / 食物 | | 인도 | 印度 / 人道 / 引導 |
| 가정 | 家庭 / 假定 | | 일신 | 一身 / 一神 |
| 조화 | 調和 / 造化 | | 기원 | 起源 / 祈願 |
| 부인 | 婦人 / 否認 / 夫人 | | **현상** | **現象** / 現狀 |
| 신성 | 神聖 / 神性 | | **신인** | **神人** / 新人 |
| 정의 | 定義 / 正義 | | **공구** | **孔丘** / 攻究 |

굵게 표시한 셋은 이 연구의 핵심어라 특히 중요하다 — **현상즉실재론**의 `現象`, **신인철학**의
`神人`, 공자를 가리키는 `孔丘`.

⚠️ 예외 단어가 **한글로 적힌** 경우(예: 한글 「이상」)는 어느 쪽인지 가릴 수 없어 **버린다.**
경미한 누락이며 한계로 수용한다.

### 4.3 stoplist — 자카드에서만 빼는 것

대명사·수량사·기능어·판독 오류로 보이는 일곱은 유사도 계산에서 제외한다.

**제외**: 其人 · 幾人 · 其者 · 一大 · 幾分 · 一一 · 此二  
**유지**: 基因 · 記者 · 一代 · 氣分 · 一日 · 差異 (읽기는 같으나 내용어다)

## 5. 처리 순서

각 자료의 `TEXT`·`RTC_TEXT` 행을 문장 묶음(`n_chunk`) 단위로 처리한다.

```
1. 한자 토큰 (2자 이상)
     stoplist면          → 버린다
     동음이의 예외면      → 한자 그대로 유지
     그 외               → 한국 한자음으로 변환

2. 한글 어절 (2자 이상)
     예외 읽기면          → 버린다 (가릴 수 없으므로)
     게이트 통과 한자어면  → 그 한글을 유지
     그 외 (고유어)       → 버린다

3. 가나                  → 무시
```

**출현은 모두 보존한다**(멀티셋). 한 묶음에 같은 낱말이 세 번 나오면 세 번 기록한다. 그 뒤
쓰임에 따라 갈린다.

- **자카드** — 묶음 단위로 `set()`을 취해 **빈도를 무시**한다.
- **빈도 분석** — `Counter()`로 출현을 전수 계수한다.

산출: `data/4_tokens/tokens_{1915,1924,개벽,월보}.csv` — 열은 `src, n_chunk_id, c, token`.

## 6. 검증 — 결론이 바뀌는가

정규화 토큰으로 자카드를 다시 내어 기존(한자-only) 결과와 견주었다.

| | 기존 | 정규화 |
|---|---|---|
| β 분포 평균 | 0.0683 | 0.0697 |
| β 분포 표준편차 | 0.0370 | 0.0371 |
| β 상위 10 멤버십 | — | **완전 동일** (진입·이탈 0) |

매개 클러스터 다섯 글이 전원 top-5를 유지했고 z값도 거의 움직이지 않았다
(C53 +4.94→+5.30 · C22 +3.79→+3.87 · C19 +2.60→+2.55 · C43 +2.63→+2.53 · C23 +2.38→+2.33).

**결론은 바뀌지 않았다.** 곧 한글 한자어 누락 편향은 실재하지만 유사도 결과에는 영향이 무시할
만하다. 정규화를 유지하는 까닭은 두 가지다 — **표기 습관이 결과를 오염시켰다는 비판에 대한
답**이고, **빈도 분석의 일관성**을 위해서다.

## 7. 알려진 한계

1. **읽기 오변환.** `刺激`이 「자격」으로 읽혀 `資格`과 충돌할 수 있다. 미해결이며, 필요하면 두
   낱말을 §4.2 예외에 넣어 분리한다.
2. **예외 단어의 한글 표기가 누락된다.** `理想`의 한글 「이상」 일부가 버려진다.
3. **코퍼스에 한자로 한 번도 안 쓰인 순수 한글 한자어는 복구되지 않는다.** 매칭에는 무해하고
   빈도에 경미한 누락이 생긴다.
4. **게이트를 통과한 오인정이 남는다.** `何者`(하자)·`支那`(지나)류의 저빈도 사례.
5. **가타카나 서양 고유명사는 제외된다.** 칸트/カント 등.
6. **읽기를 바꾸는 판독 오류는 잔존한다.** 읽기를 보존하는 오류(衣識→의식)는 자동 흡수되지만,
   읽기 자체가 달라지면 다른 낱말이 된다.

## 8. 이 단계가 수치에 미치는 영향

같은 자료에서 방식만 바꾸어도 토큰·타입 수가 달라진다.

| | 표기 방식 | 정규화 방식 |
|---|---|---|
| 1915 tokens | 39,940 | 39,782 |
| 1924 tokens | 15,871 | 15,657 |
| 1915 types | 9,529 | 9,173 |
| 1924 types | 4,512 | 4,333 |

**어느 방식의 수치인지 밝히지 않은 통계는 재현할 수 없다.** 이 저장소의 산출물은 파일명이나
문서에 방식을 표시한다.
