- Paddle의 옛한글 미인식은 예상대로.

## 시리즈 정책 v0 → v0.1 (3 규칙 추가)

기존 5규칙(`_design/2026-05-09_cheondogyo_wolbo_phase2_summary.md`):
1. 3엔진 다수결
2. 옛한글 보존
3. 천도교 호칭 보존
4. 한문 관용 우선
5. 표제·저자 위치 (reading order 우→좌)

**v0.1 추가 규칙** (본 시범에서 도출):

6. **세로 분리선 layout 식별** — 페이지 가운데를 관통하는 *세로 물결무늬 분리선*이 있는 layout 존재. 좌측이 본 기사, 우측이 이전 기사. 본 1편(가로 분리만)과 *완전 다름*. 자르기 시 가로·세로 분리선 모두 검출 필요.
7. **작은 활자 단에서 Gemini 우세, 큰 활자에서 Claude 우세** — 단별 활자 크기에 따라 주(主) 도구 우선순위 조정 가능.
8. **저자명 인식은 Claude 우선** — 작은 한자 인명에서 Claude가 더 정확.
9. **Claude의 컬럼 분리 한계** — 작은 활자 단에서 컬럼 경계를 잘못 잡을 수 있음(예: 4단을 6단으로). *인간 시각 검증 필수* 영역.
10. **Gemini의 환각 위험** — 시각상 없는 글자(예: 「不知」)를 추가하는 경우 있음. 다른 도구·인간으로 cross-check 필수.
11. **인간 시각 검증의 권위** — 자동 합의는 ~85% 자동 결정. *나머지 10-15%는 인간 직접 시각 확인이 권위*. 인간 검증 결과는 OCR 결과를 *덮어쓴다*.

이 11규칙이 시리즈 적용(75편)에서 합의 자동화 스크립트 v1(B2)의 코드화 사양 + 인간 검증 워크플로(B3) 입력.

## 본 시범의 의의

- 본 부 표본은 본 1편과 *완전 다른 layout* (세로 분리선 추가)임을 발견. 75편에 *두 가지 layout이 혼재*할 가능성. 시리즈 적용 시 단별 layout 식별이 1차 작업.
- 옛한글 자모 다수 등장(ᄒᆞᄂᆞᆫ지·ᄒᆞ얏도다·ᄒᆞ야·ᄒᆞ고 등) — (2)→(3) 변환 규칙표 v0의 정초 자료로 가치 큼.
- Claude·Gemini·Paddle의 *각 도구별 한계가 명확*해짐 → 합의 정책에 반영 가능.
